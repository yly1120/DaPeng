# 智慧农业 APP 项目详细说明

## 1. 项目定位

这是一个基于 `uni-app + Vue 2` 开发的单页物联网控制 APP，用来连接 OneNET 物联网平台上的设备，完成以下三类工作：

1. 实时查看环境传感器数据。
2. 手动控制农业设备开关。
3. 调整环境阈值参数，并把阈值同步到云端设备属性。

代码结构上，这个项目是一个“轻前端控制面板”：

- 前端界面只有一个页面。
- 没有本地状态管理库，没有路由复杂逻辑，没有组件拆分。
- 所有业务逻辑几乎都集中在首页 [`pages/index/index.vue`](c:\Users\Yly\Downloads\APP\智慧农业APP\pages\index\index.vue)。
- 前端本身不做复杂计算，主要负责“展示数据 + 发请求”。
- 真正的数据来源、设备状态、自动控制策略，实际由 OneNET 平台和设备端共同决定。

可以把这个项目理解为：

“一个连接温室/农业控制系统的手机控制面板”。

## 5. 界面控件与交互方式

### 5.1 数据展示控件

使用插值表达式直接展示变量值：

- `{{Temp}}`
- `{{Humi}}`
- `{{CO2_ppm}}`
- `{{Light}}`
- `{{Soil_Humi}}`
- `{{Soil_ph}}`

这类控件只读，不可操作。

### 5.2 开关控件

使用 Uni-app 的 `<switch />` 组件：

- `:checked="LED"` 等绑定布尔状态
- `@change="onLedSwitch"` 等绑定事件
- `color="#2b9939"` 指定打开时的绿色

这意味着：

- 当页面变量为 `true` 时，开关显示为打开。
- 用户拨动开关后，前端会向云平台发起属性写入请求。

### 5.3 滑块控件

使用 `<slider />` 组件设置阈值：

- `:value="Temp_th"` 绑定当前值
- `@change="sliderChange($event, 'slider1')"` 统一交给 `sliderChange`
- `min/max/step` 决定取值范围和步进
- `show-value` 打开组件自带数值显示

这是典型的“一个函数处理多组同类控件”的写法。

## 9. key.js 的作用与 token 工作原理

[`key.js`](c:\Users\Yly\Downloads\APP\智慧农业APP\key.js) 是整个项目接 OneNET 的关键。

### 9.1 核心函数

- `createCommonToken(params)`，定义在 [`key.js:3`](c:\Users\Yly\Downloads\APP\智慧农业APP\key.js#L3)

### 9.2 输入参数

函数要求传入：

- `author_key`
- `version`
- `user_id`

实际调用位置：

- [`pages/index/index.vue:258`](c:\Users\Yly\Downloads\APP\智慧农业APP\pages\index\index.vue#L258)

### 9.3 生成逻辑

大致流程如下：

1. 用 `Buffer.from(params.author_key, "base64")` 处理密钥
2. 读取版本号 `version`
3. 组合资源串 `userid/{user_id}`
4. 生成过期时间 `et`
   - 当前时间 + 365 天
   - 再转秒级时间戳
5. 固定摘要算法 `sha1`
6. 按 OneNET 规则拼接签名字符串：
   - `et + "\n" + method + "\n" + res + "\n" + version`
7. 用 `crypto.createHmac('sha1', access_key)` 生成签名
8. 对资源串和签名做 URL 编码
9. 最终生成 token 字符串：
   - `version=...&res=...&et=...&method=...&sign=...`

### 9.4 这个 token 的用途

前端每次请求 OneNET 时都会在 header 中带上：

```js
header: {
  authorization: this.token
}
```

如果没有这个 token，OneNET 通常不会接受请求。

## 12. APP 如何工作：完整数据流说明

这部分是理解整个项目最关键的内容。

### 12.1 读数据链路

流程如下：

1. 页面 `onLoad`
2. 生成 token
3. 页面 `onShow`
4. 调用 `fetchDevData`
5. 前端发起 GET 请求到 OneNET
6. OneNET 返回设备全部属性数组
7. 前端按数组下标把属性映射到页面变量
8. Vue 响应式更新 UI
9. 用户看到最新环境数据和设备状态

### 12.2 写开关链路

以 LED 为例：

1. 用户点击 LED 开关
2. 触发 `onLedSwitch`
3. 读取当前开关值 `true/false`
4. 设置 `switchLed_flag = 1`
5. 发起 POST 请求到 `set-device-property`
6. 请求体里写入 `{ LED: true }`
7. OneNET 把命令同步给设备或记录为目标属性
8. 后续轮询再回读最新状态

### 12.3 写阈值链路

以温度阈值为例：

1. 用户拖动温度滑块
2. 触发 `sliderChange($event, 'slider1')`
3. 前端识别这是温度阈值
4. 更新 `Temp_th`
5. 组装 `{ Temp_th: 新值 }`
6. 发起 POST 写入 OneNET
7. 设备或平台接收阈值
8. 之后轮询时再次把阈值读回来

#### 前端 APP

负责：

- 展示
- 手工控制
- 参数设置
- 定时拉取

#### OneNET 平台

负责：

- 鉴权
- 属性查询
- 属性设置
- 设备模型数据存储与转发

#### 硬件设备

负责：

- 上传实时传感器值
- 接收控制指令
- 根据阈值进行自动控制或本地逻辑判断

前端并没有写“自动控制算法”，它更像是远程监控面板。

## 13. 控制逻辑详细拆解

### 13.1 实时刷新逻辑

采用的是“固定时间轮询”方案，而不是 WebSocket 或 MQTT 长连接。

特点：

- 实现简单
- 调试方便
- 容易理解

代价：

- 实时性一般
- 请求次数固定增加
- 如果页面反复进入，可能产生多个定时器

### 13.2 开关状态同步逻辑

控制逻辑核心为：

- 本地 `switch` 绑定 `LED/Fan/BEEP/Mist/Pump`
- 云端状态由 `fetchDevData` 轮询回读
- 本地操作时先打一个 `flag`
- 下一轮轮询跳过一次覆盖

这是一种“最小成本的前后端状态冲突缓冲机制”。

### 13.3 阈值逻辑

阈值控制没有额外标志位，逻辑更直接：

- 拖动滑块
- 更新变量
- 发请求

因为滑块的值会立即显示，用户感知上已经足够顺畅。

### 13.4 页面状态和云端状态的关系

这个项目中，云端状态是“最终权威状态”，前端状态只是临时展示。

也就是说：

- 页面变量来源于接口返回
- 用户操作只是向云端写目标值
- 最终设备有没有执行成功，要以轮询回读的结果为准

## 20. 当前项目的重要问题与潜在风险

这部分很重要，后续维护一定会遇到。

### 20.1 `onShow` 中反复创建定时器

位置：

- [`pages/index/index.vue:266`](c:\Users\Yly\Downloads\APP\智慧农业APP\pages\index\index.vue#L266)

问题：

- 每次页面重新显示都会执行一次 `setInterval`
- 但代码里没有 `clearInterval`
- 如果用户多次切出切入页面，可能产生多个轮询器同时运行

后果：

- 请求越来越多
- 界面更新混乱
- 流量和耗电增加

### 20.2 缺少 `onHide` / `onUnload` 清理

首页没有清理定时器，也没有停止轮询。

### 20.3 接口缺少失败处理

所有请求基本只有 `success`，没有：

- `fail`
- `complete`
- 用户提示
- 重试机制

如果网络断开、token 失效、OneNET 返回异常，用户界面不会得到明确反馈。

### 20.4 依赖数组下标读取设备属性

位置：

- [`pages/index/index.vue:291`](c:\Users\Yly\Downloads\APP\智慧农业APP\pages\index\index.vue#L291)

问题：

- 代码直接写死 `res.data.data[15]` 这种方式
- 一旦 OneNET 设备模型属性顺序调整
- 页面映射就会全部错位

这是当前业务里最脆弱的一部分。

### 20.5 鉴权参数硬编码在前端

位置：

- [`pages/index/index.vue:258`](c:\Users\Yly\Downloads\APP\智慧农业APP\pages\index\index.vue#L258)

风险：

- `author_key`
- `user_id`
- `product_id`
- `device_name`

都直接写在前端代码里。

如果发布到客户端，这些敏感信息有泄露风险。

### 20.6 `key_th` 未在 data 中声明

位置：

- [`pages/index/index.vue:460`](c:\Users\Yly\Downloads\APP\智慧农业APP\pages\index\index.vue#L460)

影响：

- 不够规范

这个项目本是一个基于 Uni-app 的“智慧农业设备监控与控制面板”，通过 OneNET 云平台读取温度、湿度、CO2、光照、土壤湿度、土壤 pH 等实时数据，并控制 LED、风扇、蜂鸣器、喷雾、水泵等设备，同时支持设置多个环境阈值；项目结构非常简单，全部核心业务基本集中在首页一个文件中，适合快速演示和课程设计，但在定时器管理、错误处理、属性映射方式、敏感信息保护方面还有明显可优化空间。
